# AI 图片与视频工作流应用需求方案

- 文档版本：V1.0（已补充本地部署、服务器部署与后续 EXE 交付要求）
- 编写日期：2026-09-20
- 文档定位：用于确认产品范围、设计页面和拆分开发任务；不是已实现功能说明。
- 需求依据：用户提供的《ai短视视频生成流程-2.pdf》及后续确认。
- 目标形态：通过 API 调用生成模型的网站，首版同时支持本地部署和服务器部署，后续交付 Windows EXE 桌面版。

## 1. 已确认的需求与边界

1. 应用通过 API 接入 GPT Image 2 生图与 Seedance 2.0 生视频，不依赖用户此前使用的生成网站。
2. 文档中的手表、礼盒、人物、Logo、提示词均为案例，不得作为固定字段、必选素材或业务流程限制。
3. 应用支持通用创作：商品、人物、场景、风格图以及其他符合服务商要求的内容。
4. 主要解决素材搬运、提示词整理、跨工具切换、生成结果筛选和版本追溯问题。
5. 每个项目和镜头的创作内容自由填写，模板仅用于加快输入。
6. 第一版以生成可用图片、视频片段并导出为目标；最终精剪继续使用用户现有剪辑软件。
7. 本地部署和服务器部署均为首版必需能力，不是二选一；后续需要打包成 Windows EXE，复用网站的核心功能。
8. 本文规定目标行为；接口权限、模型标识、具体参数范围、费用和取消能力需要在开发前按实际服务商文档与账号实测确认，不把模型能力推测写成承诺。

## 2. 目标与首版范围

### 2.1 产品目标

让用户在一个工作台中完成：

> 准备素材 → 编写或复用提示词 → 生图或改图 → 选图 → 生视频 → 对比与采用 → 导出。

用户应能随时离开并恢复项目，不需要重新整理输入，也不需要记忆某段视频对应哪张图片、哪版提示词。

### 2.2 第一版包含

- 项目管理与镜头卡片。
- 通用素材库，支持图片与视频。
- 自由提示词编辑、可选模板、明确的参考素材绑定。
- GPT Image 2 图片生成、参考图生成与图片编辑。
- 从已有图片或已生成图片进入 Seedance 2.0 视频生成。
- 后台任务、状态恢复、错误处理和重复提交防护。
- 候选结果比较、采用标记、生成记录和来源关联。
- 单文件下载及按镜头组织的批量导出。
- 服务端 API 配置、用量记录和生成数量控制。
- 本地与服务器两种部署方式，以及对应的启动、配置、停止、备份与升级说明。
- 在结构和依赖选择上满足后续 EXE 打包条件；首版不要求立即交付 EXE。

以上生成功能须在接口验证阶段确认指定服务商的支持情况。若存在能力缺口，明确记录受影响功能及替代路径，不静默改用其他模型。

### 2.3 第一版不包含

- 通用节点拖拽、自由连线的工作流编排器。
- 在线专业剪辑时间线、复杂转场、调色和音轨编辑。
- 自动运营、内容发布和广告投放。
- 操作第三方生成网站的浏览器自动化。
- 多租户、团队角色、审批、会员和计费系统。
- 任意服务商的通用 API 插件系统。
- 未选图即自动连续生视频、自动评价并挑选最佳结果。

## 3. 用户与使用假设

首版按单人创作者使用设计。一个人可以管理多个项目，反复使用素材和模板，并同时查看多个生成任务。

部署能力已确定为同时支持本地和服务器：本地版在用户电脑运行，通过浏览器访问；服务器版在自有服务器运行，通过浏览器远程访问。后续 EXE 版提供 Windows 桌面入口，并能在本机运行完整工作台。单人使用不等于允许公开访问；服务器部署需要身份验证和私有素材访问控制。

视频配音、背景音乐、复杂多模态参考、多人协作暂不作为首版验收条件。

## 4. 核心概念

| 概念 | 含义 | 规则 |
| --- | --- | --- |
| 项目 | 一次创作任务的容器 | 保存目标、镜头、素材及可选默认设置，不强制关联商品 |
| 镜头 | 一个独立画面或视频片段的创作单元 | 保存描述、参考素材、两阶段提示词和候选结果；可以仅生成图片 |
| 素材 | 用户上传或生成得到的图片、视频 | 可被多个镜头引用；原始文件保留，预览文件另存 |
| 提示词模板 | 可复用的文字及可选变量 | 可新建、修改、复制；使用后形成镜头内可编辑文本 |
| 生成任务 | 一次明确的模型调用意图 | 输入和参数在提交时形成快照，不随后续编辑变化 |
| 生成结果 | 一次任务产生的一个或多个输出 | 记录来源任务，供预览、下载、引用与采用 |
| 采用结果 | 用户明确选定的图片或视频 | 决定后续生成输入或默认导出内容；其他候选结果保留 |

项目名称、镜头名称、素材名称由用户自定义；系统不要求存在“手表”“礼盒”“Logo”等专属实体。

## 5. 创作流程

### 5.1 文字开始的流程

1. 创建项目，填写创作目标；画幅等可设为项目默认值。
2. 新建镜头，自由描述画面，按需添加参考素材。
3. 编写生图提示词，或使用模板后修改。
4. 选择图片参数与生成数量，检查本轮提交内容。
5. 提交生图，后台处理，结果进入当前镜头。
6. 选择合适的图片；需要调整时，以该图发起图片编辑。
7. 编写视频动作、运镜等要求，确认实际输入图片。
8. 提交生视频，完成后预览并选择采用结果。
9. 按镜头顺序导出采用的视频或图片。

### 5.2 已有图片直接生视频

上传图片 → 创建或选择镜头 → 选定输入图 → 填写视频提示词 → 生视频 → 采用与导出。

不强制用户先调用生图模型，也不要求同时填写生图提示词。

### 5.3 图片编辑与局部重做

从某张候选图片发起修改，填写具体要求并提交新任务。新结果以新版本保存，原图保留。

如果修改后的图片被采用，已有视频仍保留，并提示其来源为旧图片；用户自行决定是否重新生成视频。编辑文字、换图和切换采用结果均不得自动触发付费生成。

### 5.4 只使用部分流程

用户可以仅生图并下载，也可以上传外部已有视频作为候选素材。上传已有内容是通用素材管理能力，不是首版模型调用的主要替代流程。

### 5.5 人工决定节点

默认保留“选哪张图用于视频”和“采用哪段视频”两个决定节点。未选定必需输入、提示词不完整或参数无效时，不允许提交对应任务。

## 6. 页面与交互

### 6.1 项目列表

- 创建、重命名、归档项目。
- 展示项目封面、最近更新时间、镜头数量、运行中任务数量。
- 按名称查找项目；进入后恢复到项目工作台。
- 首版以归档代替整项目永久删除，降低误删素材的风险。

### 6.2 项目工作台

采用三栏结构：

| 区域 | 内容 | 主要操作 |
| --- | --- | --- |
| 左侧镜头列表 | 镜头名称、顺序、采用结果缩略图、任务提示 | 新建、复制、重命名、调整顺序、归档 |
| 中间预览区 | 图片或视频候选结果、来源、采用标记 | 放大、播放、对比、采用、下载 |
| 右侧编辑区 | 参考素材、提示词、参数及生成操作 | 绑定素材、套用模板、生图、改图、生视频 |

图片与视频编辑区域分别保存草稿，切换镜头不能丢失未提交内容。采用自动保存，并明确显示保存中、已保存或失败；保存失败时保留输入并允许重试。

画面、动作、运镜等辅助字段可选，用户始终能直接编辑完整提示词。模板套用或其他操作需要覆盖已编辑文本时，应先提示。

运行中任务在工作台中持续可见，不强制用户留在弹窗等待。用户可以继续编辑其他镜头。

### 6.3 素材库

- 上传图片和视频，展示预览、名称、类型、尺寸或时长等元数据。
- 按名称和类型筛选，可添加标签。
- 从素材库选择多个参考文件，支持调整输入顺序。
- 按需标注用途，例如主体、场景、风格；用途标签不构成固定必填项。
- 区分上传素材和生成素材，并能够查看素材被哪些镜头引用。
- 从镜头移除素材仅解除关联；不删除原始文件。
- 首版不提供被引用素材的直接永久删除，先归档或解除引用。

### 6.4 模板管理

- 新建、编辑、复制和归档生图或视频提示词模板。
- 支持纯文本；可选支持形如 `{{主体}}`、`{{场景}}` 的变量。
- 使用模板时填写变量并预览完整提示词；存在未填变量时阻止提交。
- 套用后形成独立草稿，修改模板不回写历史镜头或已提交任务。
- 可附带默认参数，但必须按当前模型能力重新校验。
- 不默认依赖文本大模型；AI 润色作为后续功能单独接入。

### 6.5 任务与设置

任务列表按项目展示执行中、失败和完成记录，可查看输入摘要、错误、耗时及来源结果。

设置页负责已实现服务商的凭证配置或配置状态、默认模型、并发上限及用量控制。密钥输入后只展示掩码或配置状态，不返回完整值。

### 6.6 导出

- 默认导出每个镜头已采用的结果，允许手动选择其他结果。
- 按镜头顺序组织文件，文件名包含序号、镜头名和必要的版本标识。
- 支持选择图片、视频或两者；原始素材可选包含。
- 支持生成镜头清单与提示词记录，明确实际导出了哪些文件。
- 已有视频素材可手动加入导出清单，但首版不拼接为成片。
- 无采用结果的镜头在导出前显示提醒，允许明确跳过，不能静默遗漏。
- 保留原始文件；下载或打包失败时展示原因，不产生看似成功的残缺包。

## 7. 模型与 API 接入要求

### 7.1 接入原则

由应用后端调用生成 API，浏览器只与应用后端交互。分别实现图片和视频服务的必要调用，不要求两个服务商采用相同接口格式。

配置与校验以实际选定服务商文档为准。官方接口或用户选定的兼容服务都需要单独验证；“兼容”不能仅凭名称判断。

### 7.2 图片能力

目标支持 GPT Image 2 的以下操作：

- 文字生成图片。
- 使用参考图片生成画面。
- 基于已有图片和修改要求生成新版本。
- 查看候选图片并选择后续视频输入。

图片数量、格式、分辨率、画幅与质量按服务商实际支持范围展示。多候选生成不假设服务端原生批量支持；必要时拆成多个独立任务，并遵守并发限制。

### 7.3 视频能力

目标支持 Seedance 2.0 的图片输入视频生成：

- 输入图来自素材库或已生成图片。
- 独立填写动作与镜头运动提示词。
- 按实际支持范围选择时长、画幅、分辨率等参数。
- 获取任务标识并查询状态，下载和归档最终视频。

纯文生视频、首尾帧、多图、音频和视频参考可列为后续能力；只有在选定接口完成验证后才显示相关控件，不以产品名称推断支持。

### 7.4 参数和素材校验

- 项目默认参数用于方便填写，不能绕过模型限制。
- 提交前校验文件类型、尺寸、大小、数量和必填参数。
- 例如用户目标为 9:16 时，只有接口确实支持相应尺寸或比例才能直接提交；需要裁切或转换时应明确告知，不静默处理。
- 参考素材顺序和提示词引用保持一致；记录本次实际提交的对应关系。
- 外观、文字、品牌与人物一致性是用户选片依据，不承诺模型可以绝对保持。

## 8. 任务状态与可靠性

### 8.1 状态定义

| 状态 | 含义 | 用户可执行的操作 |
| --- | --- | --- |
| 排队中 | 本地已保存任务，尚未向服务商提交 | 查看输入、取消排队 |
| 提交中 | 正在发送请求 | 查看状态，不重复提交同一请求 |
| 生成中 | 服务商已受理或同步调用仍在处理 | 离开页面、继续其他镜头 |
| 保存中 | 已获得结果，正在保存到应用存储 | 查看状态，等待归档 |
| 已完成 | 结果已归档并可访问 | 预览、采用、下载、再次生成 |
| 失败 | 已确认失败，或结果保存失败 | 查看具体阶段，选择对应重试 |
| 待核实 | 超时或断线，无法确认是否已受理或完成 | 刷新、核对；明确重复计费风险后再决定重做 |
| 已取消 | 本地排队取消，或服务商明确确认取消 | 查看历史记录 |

这些是应用内部状态，不要求服务商提供同名状态。同步图片请求与异步视频任务分别实现相应映射。

### 8.2 必须实现的行为

1. 付费请求提交前，先保存任务和输入快照。
2. 同一次点击或网络重试使用稳定的请求标识，后端防止重复建单；不把用户主动“再生成一次”误判为重复。
3. 获得服务商任务 ID 后立即保存，用于后续查询及恢复。
4. 浏览器关闭不终止仍在运行的后台服务中的任务；重开页面从已保存状态恢复。本地电脑关机、休眠或服务停止后不保证继续执行查询与归档，恢复运行后按任务状态继续处理。
5. 后台进程重启后恢复可查询任务；无法确认同步请求结果时进入待核实，不自动再发一次付费请求。
6. 状态查询错误与生成失败分开处理；临时查询失败不立即判定生成失败。
7. 对已知受理任务的查询可按退避策略重试；结果保存失败优先重试保存，不重新生成。
8. 服务商已受理后，仅在接口支持时提供实际取消；不支持时不得把隐藏任务或停止查询称为取消生成，也不承诺退款。
9. 不展示虚构进度百分比；接口只返回阶段时就展示阶段和已等待时间。
10. 一个候选任务失败不覆盖同镜头其他成功结果；多个任务完成顺序不同也不得相互覆盖。

## 9. 版本与来源追溯

每次生成至少记录：

- 所属项目、镜头和任务类型。
- 服务商、请求使用的模型标识，以及接口返回的版本信息（若有）。
- 实际提交的提示词、参数、参考素材 ID 和输入顺序。
- 发起修改或视频生成时的来源图片。
- 本地请求标识、服务商任务 ID（若有）。
- 创建、提交、完成时间与错误阶段。
- 所有输出文件、用量信息及费用信息的来源。

提交后的记录不可随草稿变化而修改。用户能从视频追溯到输入图，再追溯到生成该图的素材与提示词。

切换采用图片不自动删除旧视频；切换采用视频不影响其他候选版本。多个候选可保存，每个镜头默认各采用一张图片和一段视频。

复制镜头默认复制草稿、素材引用和参数，不触发生成，也不把原镜头的任务历史当成新任务；原有素材仍可复用。

## 10. 用量与费用控制

- 每次生成前明确展示候选数量以及会启动多少个任务。
- 已知计价规则时显示估算与计算依据；无法可靠估算时明确标为未知。
- 分开记录“预估费用”“接口返回费用”“按用量计算费用”，没有数据不能写成零。
- 设置每轮最大数量和并发数，避免误触发大量任务。
- 支持项目预算提醒；费用存在延迟、估算或未知项时说明预算监测不保证绝对不超额。
- 已知费用或估算达到设置阈值时，阻止静默新增任务并提示用户处理；运行中的任务可能继续产生费用。
- 不设置默认无限重试，不因换图、改提示词或刷新自动调用付费接口。
- 无法取消的任务费用以服务商规则为准，不以应用中的操作状态推断退款。

## 11. 文件、凭证与数据保护

- API 密钥只保存在服务端环境或适当的加密配置中，不进入前端包、页面数据、日志或项目导出。
- 上传文件做真实类型、扩展名与大小校验；文件存储名由系统生成，展示名与存储路径分离。
- 素材默认私有；需要提供给模型服务商时，使用其支持的上传方式或有效期受控的签名地址，不公开整个素材库。
- 结果文件下载需要校验来源与重定向，避免后端读取非预期网络地址。
- 原始素材、采用结果和任务记录分别持久保存，不只保存可能过期的远程结果地址。
- 生成历史只保存必要的请求信息，避免记录密钥和可重复访问的敏感地址。
- 若部署到云端，页面、文件下载和后台接口都必须有访问控制；本机版本默认仅监听本机。
- 归档不删除文件。永久删除、自动清理和存储配额策略另行明确，不默认清空用户素材。
- 备份覆盖数据库和素材文件；部署交付时提供备份、恢复方式及容量说明。

## 12. 技术实现建议

首版采用一个 Web 应用、一个数据库、一个文件存储，以及可独立于浏览器运行的后台任务处理。

| 模块 | 职责 | 首版约束 |
| --- | --- | --- |
| Web 界面 | 项目、素材、镜头编辑、预览、导出 | 优先桌面浏览器；表单、焦点与操作按钮具备基础可访问性 |
| 应用后端 | 输入校验、访问控制、模型调用、记录 | 密钥留在后端，按两个模型的实际接口实现 |
| 数据库 | 项目、镜头、素材索引、模板、任务与结果关联 | 保证刷新和重启可恢复，不以浏览器本地存储为唯一数据源 |
| 文件存储 | 原始图片、视频、预览和导出文件 | 本机目录或私有对象存储，根据部署方式选择 |
| 后台任务处理 | 提交、轮询、归档、重试与导出 | 首版可使用数据库任务表，不预设引入独立消息队列 |

不在需求阶段绑定尚未选择的框架或供应商。技术选型必须同时满足本地部署、服务器部署和后续 Windows EXE 打包，不能仅适用于某个云平台的专属运行环境。

若后续增加多个后台处理实例，需要补充任务领取和锁定机制，确保同一任务不被多个实例重复提交。

### 12.1 网站的两种部署方式（首版必需）

| 形态 | 运行位置与访问方式 | 数据与任务 | 交付要求 |
| --- | --- | --- | --- |
| 本地部署网站 | 在用户电脑启动应用后，通过本机浏览器访问 | 数据和文件保存在可配置的本地目录，任务由本机后台处理 | 提供依赖说明、配置示例、启动与停止命令，以及备份、恢复、升级说明 |
| 服务器部署网站 | 在用户自有服务器启动应用，通过受控地址访问 | 数据和文件保存在服务器持久目录或配置的私有对象存储，任务由服务器处理 | 提供构建与部署说明、身份验证、HTTPS 接入说明、进程管理与持久存储配置 |

- 两种部署使用同一套源代码和数据结构，以配置区分端口、访问地址、数据目录和密钥，不分别维护两套业务实现。
- 本地运行无需先部署远程应用服务器。模型生成仍通过外部 API 完成，需要网络和有效凭证；“本地部署”不表示模型离线运行。
- 首版本地以用户当前 Windows 环境为验收目标；服务器操作系统在技术选型时确定并列入交付说明。
- 不写死 Windows 盘符、路径分隔符或固定域名；核心逻辑不得依赖浏览器以外的桌面专属接口。
- 本地默认仅监听回环地址；本地接口仍需防止其他网站或非预期请求触发付费操作。本地和服务器均不能把模型密钥下发给前端。
- 本地参考素材不能直接以本机路径或 localhost 地址交给远程模型。需使用服务商支持的文件上传或受控的临时访问方式，并纳入本地完整链路验收。
- 服务器版的任务由常驻后台处理，不依赖用户浏览器或单次网页请求持续连接。
- 数据目录与程序目录分离；更新程序、重建容器或重新部署不得清空用户数据。采用容器部署时必须配置持久卷，但不要求用户必须安装容器软件才能本地运行。
- 支持将数据库与素材完整备份后迁移到另一部署环境；迁移前停止原实例的任务处理，在目标实例核对服务商任务状态后恢复，避免两端重复提交。路径按目标环境重新配置，凭证安全配置，不默认随普通项目导出传播。
- 两个独立部署之间不自动同步数据；实时同步不属于当前范围。

### 12.2 为 EXE 复用保留的实现约束

- 页面通过应用接口访问数据，不直接耦合具体磁盘路径或桌面 API。
- 生成调用、任务管理与数据存储逻辑由后端统一实现，桌面版复用同一实现。
- 桌面封装只增加窗口、启动与退出管理、必要的文件系统交互及安装打包，不重新实现一套镜头工作流。
- 在技术选型时验证：Web 页面可被桌面容器承载，后端及其依赖能够随 Windows 发行包运行，数据可在升级后继续使用。
- 不提前引入多套桌面框架或自制插件系统；具体封装技术在实现前根据已有技术栈和打包验证选择。

### 12.3 Windows EXE 的后续交付要求

1. 用户可双击启动桌面工作台；发行包提供应用所需运行环境或明确安装所需组件，不要求用户自行安装开发工具链、输入开发命令或另外搭建应用服务器。
2. 默认在本机运行完整工作台，复用网站能力；不是仅打开远程网站地址的快捷方式。
3. API 凭证保存在本地后端的安全配置中，不内置开发者凭证；上传和生成数据保存在用户可写的数据目录，不写入安装目录。
4. 启动时处理端口占用和重复启动，不能让多个实例同时处理同一批任务。辅助进程默认无额外命令行窗口。
5. 关闭窗口默认正常退出桌面程序及其管理的本地服务；存在运行中任务时先说明影响并允许用户返回继续等待，不静默遗留后台服务。
6. 退出前持久保存任务状态；服务商可能继续执行已受理任务。再次启动后查询可恢复任务，无法确认的进入待核实，不承诺退出即取消生成或退款。
7. 网络断开、电脑休眠、程序重启后，已保存草稿与素材仍可恢复；恢复生成查询和归档时不重复提交付费请求。
8. 程序升级保留用户数据，涉及数据结构变更时提供迁移与备份方式；安装、升级和默认卸载不得静默删除创作数据。
9. 提供本地网页版到 EXE 版的数据迁移说明；同一数据目录同一时间只由一个后台实例处理。
10. 在约定 Windows 版本的无开发环境机器上验证安装或解压、启动、配置凭证、完整生成流程、导出、退出和升级。

EXE 的安装包或便携包形式在打包阶段确定。自动更新、连接远程服务器模式及跨设备同步不作为首次 EXE 交付要求。

## 13. 开发阶段与交付物

### 阶段 A：API 接入验证

- 确认两个模型的服务商、API 文档、账号权限和计费方式。
- 用非固定业务样例验证文字生图、参考图生图、图片编辑、图片生视频。
- 验证文件传递、参数范围、任务查询、错误返回及结果归档。
- 输出已验证能力清单、样例结果、实际耗时和可取得的用量信息。
- 测试通过后再确定页面参数范围和模型调用实现；不以网页产品宣传代替接口验证。

### 阶段 B：第一版工作台

交付本文首版范围：项目与镜头、素材库、模板、两个模型接入、选片、任务恢复、来源记录和导出。

在本地环境和服务器环境分别完成部署与完整真实项目验收，并交付两套操作说明，不只验证按钮能够调用接口。

### 阶段 C：Windows EXE 交付（已确定的后续需求）

- 复用网站页面、业务逻辑、接口适配及数据结构，完成桌面封装和本地运行时打包。
- 提供可双击启动的 Windows EXE 或以 EXE 安装的桌面应用，无需用户手动启动开发服务。
- 验证本地配置、素材存储、任务恢复、正常退出、升级保留数据，以及与本地网页版的数据迁移。
- 按第 12.3 节验收。EXE 交付是已确定的后续范围，不是可选候选功能。

### 阶段 D：根据使用数据增加功能

候选内容包括批量创建镜头、变量批量替换、项目复制、AI 提示词润色、稳定模板连续执行、更多视频参考模式、粗剪预览和团队协作。

上述均不默认进入首版。新增前先确认它解决的是实际重复操作，并补充相应费用与异常处理。

## 14. 第一版验收标准

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| AC-01 | 通用创作 | 创建不涉及商品的风景或人物项目，无需填写手表、礼盒、Logo 等字段即可使用 |
| AC-02 | 完整链路 | 在应用内完成素材准备、生图、选图、生视频、采用和下载，不需要打开生成网站 |
| AC-03 | 图片直达视频 | 上传已有图片后直接生视频，不被要求先运行生图 |
| AC-04 | 提示词与模板 | 自由编辑可用；模板可修改；缺失变量会阻止提交；模板变更不影响历史任务 |
| AC-05 | 图片编辑 | 从候选图片提交修改后产生新结果，原图与编辑来源保留 |
| AC-06 | 输入传递 | 视频任务使用用户明确选定的图片与对应提示词，来源在界面可查 |
| AC-07 | 版本隔离 | 修改草稿和换图不更改已提交任务，也不自动调用接口；旧视频仍指向旧输入图 |
| AC-08 | 页面恢复 | 生成中刷新、关闭并重新打开页面后，任务及已保存草稿可恢复 |
| AC-09 | 后台恢复 | 重启后可查询任务继续跟踪；状态不确定的任务进入待核实，不自动重复付费 |
| AC-10 | 重复提交 | 同一次请求的重复点击与网络重试不重复建单；主动再次生成会形成新任务 |
| AC-11 | 部分失败 | 一个候选失败不影响其他结果；失败原因和可执行的恢复动作清楚可见 |
| AC-12 | 归档恢复 | 模型生成成功而本地保存失败时，可重试保存，不直接重新生成 |
| AC-13 | 取消语义 | 排队任务可取消；已提交任务的按钮与提示符合服务商实际取消能力 |
| AC-14 | 参数校验 | 不支持的尺寸、时长、文件类型或数量被清楚提示，不静默忽略或变更 |
| AC-15 | 结果选择与导出 | 可比较候选、切换采用结果；导出顺序正确，文件可打开，缺失镜头有提示 |
| AC-16 | 费用显示 | 未知费用明确为未知；数量、并发限制有效；刷新和保存草稿不触发付费 |
| AC-17 | 凭证与访问 | 浏览器响应、日志和导出不含密钥；云端未授权访问不能读取素材或调用生成接口 |
| AC-18 | 素材复用 | 同一素材可用于多个镜头；解除单处引用不会破坏其他镜头和历史记录 |
| AC-19 | 创作内容安全保存 | 切换镜头不丢草稿；保存失败可见且输入保留；归档不自动删除源文件 |
| AC-20 | 真实项目交付 | 至少一个真实项目能导出完整可用素材，并记录人工操作时间、采用比例与可取得的生成成本 |
| AC-21 | 本地部署 | 按交付说明在 Windows 本机启动网站，完成图片与视频 API 链路、保存和导出；停止后无遗留的应用服务 |
| AC-22 | 服务器部署 | 按交付说明在约定服务器环境部署并受控访问；浏览器断开后后台仍能处理任务，未授权访问被阻止 |
| AC-23 | 数据持久化与迁移 | 重启和重新部署不丢数据；按备份恢复流程迁移后，项目、素材与来源关联可用，任务不被双端重复提交 |
| AC-24 | 桌面打包准备 | 在技术选型验证记录中证明前端与后端能够随 Windows 发行包运行；核心流程不依赖云平台专属运行服务 |

AC-21 至 AC-24 属于网站首版验收；完整 EXE 功能在阶段 C 按第 12.3 节单独验收。

## 15. 效果评估

上线前后选择规模相近的实际项目对比：

- 每个项目的人工操作时间，单独计算等待模型的时间。
- 从输入准备到获得可用素材的总耗时。
- 图片与视频分别统计的候选数量、采用数量和返工次数。
- 每个采用镜头的生成成本；费用未知项单独列出。
- 在生成阶段离开工作台的次数。

首版先建立记录和对比方法，不提前承诺固定百分比的效率提升或模型出片成功率。
